## Flagged Assumptions

1. **Spec-less edge probe: PERF-01's row came back `unclassified` and therefore stays `unresolved`.**
   Per the probe protocol an `unclassified` row is never auto-backstopped, so no probe-derived
   predicate exists for PERF-01. Surfaced here rather than silently dropped. PERF-01 is covered
   instead by the three numeric thresholds asserted against parsed Lighthouse JSON across four runs.
   PERF-02's three rows (adjacency, empty, ordering) ARE resolved, as the three `edge lift` entries in
   `must_haves.truths`.
2. **The Docker daemon was NOT running when this phase was planned.** `docker` is installed at
   `/usr/local/bin/docker`, but `docker info` failed with "Cannot connect to the Docker daemon". Task 1
   therefore attempts to start it and polls, and falls back to `astro preview` — the fallback
   `05-CONTEXT.md` itself sanctions ("docker container or `astro preview`"). The fallback is NOT
   equivalent: it serves the same `dist/` but without the real `nginx.conf`, so cache headers,
   compression, and the `/sitemap.xml` route are not exercised. Task 1 records which server was used
   and, on the fallback path, pushes the nginx-specific assertions onto the DEPLOY.md live checklist
   rather than marking them passed.
3. **The `Dockerfile` builds inside the image and declares no `ARG`/`ENV` for `PUBLIC_LISTMONK_*`.**
   An in-image build would therefore omit the newsletter section, contradicting the requirement that
   the perf run measure the production-shaped page. Task 1 instead builds locally with the variables
   set and bind-mounts the resulting `dist/` plus the real `nginx.conf` into `nginx:stable-alpine`.
   This exercises the identical serving layer with the correct content and touches no deploy artefact.
   How Coolify supplies those build-time variables to the Dockerfile is a deploy concern already owned
   by DEPLOY.md Section 2, not a Phase 5 change.
4. **`npx`-pulled tool versions drift.** RESEARCH verified `lighthouse@13.4.1` and `@axe-core/cli@4.12.1`
   flags by running `--help` in this repo, and its validity window runs to 2026-09-07. Task 1 re-checks
   `--help` if a flag is rejected rather than guessing, and RESEARCH's anti-pattern list already
   records that `--preset=mobile` does not exist and `--form-factor=mobile` is the correct flag.
5. **`@axe-core/cli` depends on a bundled chromedriver that may fail to launch locally.** RESEARCH
   names `agent-browser` plus axe-core injection as the sanctioned fallback; Task 2 takes it only after
   the primary path demonstrably fails, and records which path produced the result.
