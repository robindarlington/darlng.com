<objective>
Give every page of darlng.com a real social card: a build-time Sharp generator that composites each
release's artwork onto a 1200x630 brand canvas, wired into `npm run build` as a `prebuild` hook, and a
`Layout.astro` head extended with absolute-URL Open Graph + Twitter Card meta that all six pages pass
through.

Purpose: SEO-01 — when a fan pastes a darlng.com link into a DM, a group chat, or a timeline, the
unfurl shows the release artwork rather than a blank rectangle. This is the phase's only user-visible
capability.
Output: `scripts/generate-assets.mjs`, five 1200x630 PNGs under `public/og/`, the `prebuild` hook, and
the extended `Layout.astro` head consumed by `index.astro`, `listen/[slug].astro`, and `404.astro`.
</objective>

## Flagged Assumptions

1. **RESEARCH Open Question 1 — RESOLVED during planning, no longer an assumption.** The exact
   `sharp.composite()` option keys were executed against this repo's installed `sharp@0.34.5`:
   `sharp({create:{width:1200,height:630,channels:4,background:'#0A0908'}}).composite([{input,
   gravity:'center'}]).flatten({background:'#0A0908'}).png()` produced a valid 1200x630 PNG from
   `src/assets/releases/eseriani.jpg`. RESEARCH assumption A1 is discharged.
2. **RESEARCH assumption A2 (hand-rolled ICO byte layout, MEDIUM confidence) — RESOLVED during
   planning.** The 22-byte-offset `ICONDIR` + `ICONDIRENTRY` layout was built and the output
   identified by `file(1)` as `MS Windows icon resource - 1 icon, 32x32 with PNG image data`. The
   exact byte layout is transcribed into `05-02` Task 1, and `file` is wired as its acceptance gate.
3. **Spec-less edge probe: SEO-01's three rows (adjacency, empty, ordering) are resolved here as
   `covered` truths** — see the last three `must_haves.truths` entries. SEO-02's and PERF-01's rows
   came back `unclassified` and, per protocol, stay `unresolved`; they are surfaced as flagged
   assumptions in `05-02` and `05-03` respectively, never silently dropped.
4. **Source artwork is square and >= 1254px.** All four covers are 1254x1254 JPEGs (verified this
   session). The generator resizes art to 630x630 to fit the canvas height, which is a downscale for
   every current release. If a future release ships smaller artwork, the composite would upscale;
   Task 1 therefore fails loudly on any source narrower than 630px rather than silently blurring.
5. **RESEARCH assumption A3** (`new URL(path, Astro.site)` as the idiomatic absolute-URL pattern) is
   standard `URL` constructor behaviour, not Astro magic — low risk, and the acceptance criteria
   assert the resulting absolute strings directly rather than trusting the mechanism.

`website/scripts/generate-assets.mjs` (per D-03, D-12; RESEARCH Patterns 1 and 2). New ESM script
importing only `sharp` and `node:` builtins — install nothing. Resolve paths from
`path.dirname(fileURLToPath(import.meta.url))` exactly as `check-contrast.mjs` does. Declare the
canvas constants `1200` wide, `630` tall, and the background `#0A0908` taken from the `--color-bg`

and must be updated together with it. Export nothing; this is a CLI entry point.

The generation routine takes a source JPEG path and an output path and: reads the source metadata
first and throws a descriptive `Error` naming the file if either dimension is below 630, so a future
low-resolution cover fails the build loudly instead of shipping an upscaled blur; resizes the art to
630x630 with `fit: 'cover'` into a buffer; then creates a 1200x630 4-channel canvas filled with the
brand background, composites the art buffer at `gravity: 'center'`, calls `.flatten()` with the same
background so the PNG carries no alpha, and writes PNG output with `toFile`. These exact option keys
were executed against this repo's `sharp@0.34.5` during planning and produce a valid 1200x630 PNG —
transcribe them rather than re-deriving. Create `public/og/` with a recursive mkdir before writing.
Print one line per written file with its path and final pixel dimensions read back from sharp, so the
build log is self-evidencing.

In this task the script generates exactly one file: `public/og/home.png` from
`src/assets/releases/eseriani.jpg` (D-03: the home card is Eseriani-based). Structure the routine so
Task 2 adds a loop over `releases` rather than rewriting it.

Do NOT route these images through `astro:assets` / `<Picture>` / `<Image>`. Astro's image pipeline
hashes output filenames into `_astro/`, and a social card URL must stay constant across builds
(RESEARCH Anti-Patterns). `public/` deliberately bypasses that pipeline; that is the point.

existing entries untouched.
