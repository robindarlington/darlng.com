  <files>website/nginx.conf</files>
  <action>
    Complete the serving layer with the path-differentiated caching D-08 specifies. Astro content-hashes everything under `_astro/`, so those files can be cached for a year; HTML filenames are stable, so caching them at all makes a deploy invisible until a hard refresh.

    Implement it as a server-level default plus one override, NOT as a pair of competing regex locations. At the `server` level add `add_header Cache-Control "no-cache" always;`. Then add `location ^~ /_astro/ { add_header Cache-Control "public, max-age=31536000, immutable" always; }`.

    Two reasons for this shape. First, nginx's `add_header` does not inherit into a location that declares its own — so the location block is a clean override of the server default, which is precisely the semantics D-08 wants. Second, a regex block keyed on an html suffix would miss a request for `/`, because the `index` directive and the try_files chain reach `index.html` by different routes with different location-rematch behaviour; a server-level default is immune to that whole class of subtlety. The result is a superset of D-08: HTML gets `no-cache` as specified, hashed assets get the immutable year as specified, and the handful of other unhashed root files (favicon, sitemap, robots) also revalidate — which is correct for unhashed files. Use the `always` flag on both so the header is emitted on error responses too.

    Rebuild the image and re-run the container. Discover the hashed asset filename from the build output rather than assuming one — read it out of `website/dist/_astro/` at verification time. Never hardcode a hash.

    If the Docker daemon is unavailable, take the same documented fallback as Tasks 1 and 2 (structural grep assertions on `nginx.conf`) and record the degradation explicitly in the SUMMARY.
  </action>
