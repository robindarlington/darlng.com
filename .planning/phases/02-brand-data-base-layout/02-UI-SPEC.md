| Property | Value |

| Font | Display: **Unbounded** (`@fontsource-variable/unbounded`) · Body: **Manrope** (`@fontsource-variable/manrope`) |

### Why this pairing ("make it pop," not corporate)

The Eseriani cover art (`/Users/rob/Desktop/DARLNG/ESERIANI/ESERIANI.jpg`) is warm and earthy: rust-red hand-lettering, ochre/gold brush strokes, tan savanna tones, small turquoise/teal beadwork accents against a warm sky. The site itself stays dark/cinematic (near-black), so the brand system pulls **one** jewel tone forward — a saturated turquoise lifted from the beadwork in the photo — as the sole accent, and reserves the rest of the palette for near-black neutrals and warm off-white text. This keeps the site visually distinct from the daylight/earth-tone cover art it showcases while still feeling like it belongs to the same world.

- **Unbounded** (display, headings, wordmark): a bold, geometric, slightly expressive grotesk built for contemporary music/culture branding — reads as confident and current, not corporate-SaaS (rules out Inter/Helvetica-style safe choices).
- **Manrope** (body, UI labels, nav): clean, warm, highly legible grotesk that doesn't compete with Unbounded's character — keeps body copy readable at small sizes on dark backgrounds.
- Both ship as **variable fonts** (`@fontsource-variable/*`) — one file covers the full weight range, self-hosted (no Google Fonts network call), preloadable via Astro's native font API.

## Color Tokens

All values below are exact hex, architected as a single swappable accent per CONTEXT.md's explicit constraint: retinting for a future release is a one-line change to `--color-accent` in `@theme`.

### `@theme` block (Tailwind 4 CSS-first — reference for `website/src/styles/global.css`)

```css
@import "tailwindcss";

@theme {
  /* Surfaces — 60/30 split */
  --color-bg:          #0A0908;  /* 60% — page background, dominant surface */
  --color-surface:     #171310;  /* 30% — header, footer, cards, section bands */

  /* Text */
  --color-text:         #F5F1EA; /* primary body + heading text (warm off-white) */
  --color-text-muted:   #8C8378; /* secondary/meta text, captions, copyright line */

  /* Accent — 10%, ONE swappable jewel token */
  --color-accent:       #2DD9C5; /* jewel turquoise, derived from Eseriani beadwork */

  /* Semantic (second color, non-accent) */
  --color-error:        #F0605E; /* form validation failures only (Phase 4) */

  /* Fonts */
  --font-display: 'Unbounded Variable', ui-sans-serif, system-ui, sans-serif;
  --font-body:    'Manrope Variable', ui-sans-serif, system-ui, sans-serif;

  /* Radius */
  --radius-card: 0.5rem;   /* 8px — cards, cover art, inputs */
  --radius-pill: 9999px;   /* buttons, icon circles */
}
```

Formula: WCAG relative-luminance contrast ratio, verified via script (`python3`, sRGB→linear→luminance→ratio). Full pairs tested:

| Pair | Foreground | Background | Ratio | AA text (4.5:1) | AA large/UI (3:1) |
|------|-----------|------------|-------|------------------|---------------------|
| Body text on bg | `#F5F1EA` | `#0A0908` | **17.67:1** | PASS | PASS |
| Body text on surface | `#F5F1EA` | `#171310` | **16.40:1** | PASS | PASS |
| Muted text on bg | `#8C8378` | `#0A0908` | **5.34:1** | PASS | PASS |
| Muted text on surface | `#8C8378` | `#171310` | **4.95:1** | PASS | PASS |
| Accent as text on bg | `#2DD9C5` | `#0A0908` | **11.22:1** | PASS | PASS |
| Accent as text on surface | `#2DD9C5` | `#171310` | **10.42:1** | PASS | PASS |
| Dark text on solid accent fill (buttons) | `#0A0908` | `#2DD9C5` | **11.22:1** | PASS | PASS |
| Error text on bg | `#F0605E` | `#0A0908` | **6.20:1** | PASS | PASS |
| Error text on surface | `#F0605E` | `#171310` | **5.75:1** | PASS | PASS |

**Rule triggered by the autonomous brief does NOT apply:** the pure accent (`#2DD9C5`) already clears 4.5:1 as normal-size text (11.22:1 on bg). No separate `accent-text` compliant variant is required — the single accent token may be used for both text and decorative purposes. (Design guidance, not an accessibility requirement: prefer accent for large/emphasis text and decorative use — glows, underlines, icons, CTA fills — over small-print body copy, to keep it feeling special rather than diluted.)

### 60/30/10 usage contract

| Role | Token | Reserved for |
|------|-------|---------------|
| Dominant (60%) | `--color-bg` | `<body>` background, all full-bleed page sections, the majority of the viewport |
| Secondary (30%) | `--color-surface` | Header bar, footer band, any card/panel background, code/quote blocks — visually "one step up" from the page |
| Accent (10%) | `--color-accent` | **Exclusively:** primary CTA button fill, active/hover state on links and nav items, `focus-visible` outline ring, icon hover/focus glow, `::selection` background, the decorative glow/gradient wash behind the hero (Phase 3), section-divider accents. **Never** used for large background fills, default body text color, or default icon color. |
| Semantic (error) | `--color-error` | Form validation error text/border only (Phase 4 newsletter form). No destructive actions exist in v1 scope (no delete/unsubscribe UI) — this token exists solely for "invalid email" / "submission failed" states. |
| Semantic (success) | reuses `--color-accent` | Phase 4 "Check your inbox to confirm" success state reuses the accent (teal already reads as affirming/positive) rather than introducing a third hue — keeps the single-jewel-accent architecture intact. |

`::selection { background: var(--color-accent); color: var(--color-bg); }` — an explicit "pop" touch per the autonomous brief (decisive accent use via glows/selection, not sprinkled).

## Typography

Two families, two weights each (four weight instances total), four core sizes for this phase's scope. Both are variable fonts — the packages below install the full weight range; declared weights are the values actually used in CSS.

**Explicit exception to the "max 2 font weights" rule (documented, not accidental):** this system declares **4 weight instances total — 2 per family, 2 families, zero cross-family mixing.** The two families serve strictly non-overlapping roles (Unbounded = display/headings only, Manrope = body/UI only), so within each family the "2 weights max" rule is honored exactly: Unbounded never uses a 3rd weight, Manrope never uses a 3rd weight, and no element ever chooses between more than 2 weight options for its own family. This mirrors the 44px spacing exception pattern below — state the rule, state the deviation, justify it. The alternative (collapsing to literally 2 weights site-wide) was rejected because it would force either flattening the display family down to one weight (losing the hero-vs-heading hierarchy that "make it pop" depends on) or forcing body labels/buttons to rely on color/size alone at 14–16px, which is a weaker legibility signal than weight on a dark background. If the checker's black-letter rule is meant as a strict global cap rather than a per-family cap, the fallback is to drop Unbounded 800 (headlines render at 700 like section headings, differentiated by size only) and drop Manrope 600 (nav/labels differentiated by size/letter-spacing/color instead of weight) — noted here as the pre-agreed fallback so a future revision doesn't need to re-litigate this decision.

### Fontsource install

```bash
npm install @fontsource-variable/unbounded@^5.2.8 @fontsource-variable/manrope@^5.2.8
```

- `@fontsource-variable/unbounded` — variable weight axis 200–900 confirmed on Fontsource
- `@fontsource-variable/manrope` — variable weight axis 200–800 confirmed on Fontsource; default import `@fontsource-variable/manrope` resolves the `wght` axis

### Font-face import (global.css or via Astro's native font API — either works; native API preferred for auto-preload)

```css
@import "@fontsource-variable/unbounded";
@import "@fontsource-variable/manrope";
```

| Family | Weight | Token usage |
|--------|--------|-------------|
| Unbounded (display) | 700 (Bold) | Section headings, wordmark |
| Unbounded (display) | 800 (ExtraBold) | Hero/page headline only (largest size) |
| Manrope (body) | 400 (Regular) | Body copy, paragraphs |
| Manrope (body) | 600 (SemiBold) | Nav links, labels, buttons, emphasis |

|------|------|--------|--------|-------------|
| Meta/label (`text-sm`) | 14px | Manrope | 400 or 600 | 1.5 |
| Body (`text-base`) | 16px | Manrope | 400 | 1.5 |

### Wordmark treatment

"DARLNG" is a **typographic wordmark only** — no logo asset exists or is planned this phase.

- Font: Unbounded 700 (Bold)
- Case: uppercase
- Letter-spacing: `tracking-wide` (0.025em) — gives the geometric grotesk a bit of poster-like air
- Size: `text-lg` (24px) in the header; may render larger (`text-xl`, 40px) standalone in the footer brand block
- Color: `--color-text` by default; `--color-accent` on hover/focus (200ms ease transition) when the wordmark is a link to `/`
- No drop shadow, no gradient fill — flat color, let the type do the work

## Spacing Scale

Tailwind 4's default `--spacing` (0.25rem = 4px) already generates our 8-point scale via standard numbered utilities — no custom spacing tokens needed in `@theme`. Use these exact utility numbers:

| Token | Value | Tailwind utility | Usage |
|-------|-------|-------------------|-------|
| xs | 4px | `-1`, `gap-1` | Icon-to-label micro gaps |
| sm | 8px | `-2`, `gap-2` | Compact element spacing (icon internal padding) |
| md | 16px | `-4`, `px-4` | Mobile container gutter, default element spacing |
| lg | 24px | `-6`, `px-6` | Tablet container gutter, card padding |
| xl | 32px | `-8`, `px-8` | Desktop container gutter, layout gaps |
| 2xl | 48px | `-12`, `py-12` | Section padding (mobile) |
| 3xl | 64px | `-16`, `py-16` | Section padding (desktop), major page breaks |

**Exception:** interactive icon-only tap targets (social follow links) use a **44×44px minimum** hit area (`min-h-11 min-w-11` = 2.75rem = 44px — a happy coincidence with Tailwind's default `11` step) even though 44 is not on the 8-point scale. This is a WCAG 2.1 SC 2.5.5 target-size accommodation, applied via padding around an 18–20px visual glyph, not by inflating the glyph itself.

## Layout & Responsive Contract

Mobile-first. Test viewports: **375px / 768px / 1440px** (per CONTENT.md's browser-test workflow). Tailwind 4 default breakpoints are used as-is (no custom breakpoints needed):

| Breakpoint | Width | Role |
|------------|-------|------|
| (default) | 0–767px | Mobile — single column, stacked header/footer |
| `md:` | ≥768px | Tablet — header gains breathing room, footer may go 2-col |
| `lg:` | ≥1024px | Small desktop |
| `xl:` | ≥1280px | Desktop — full multi-column layout, container reaches its max-width |

1440px (the third test viewport) falls between `xl` (1280) and `2xl` (1536); the container caps at 1280px and centers with extra `--color-bg` on either side at 1440px — verify visually that this reads as intentional (centered content column), not as "not using the screen."

### Skeleton page focal point

The Phase 2 skeleton index page's single explicit focal point: **the cover-art media element** (the Sharp/`<Picture>`-processed Eseriani thumbnail), not the type-scale/color-swatch demo text. Rationale — it is the one element on this bare-tokens page that is a real asset from the actual product (not a placeholder or a font specimen), it proves the image pipeline (Sharp AVIF/WebP output, success criterion 4) with something visually alive against the near-black background, and it previews what Phase 3's hero will do at scale. Composition: the cover art renders large relative to the surrounding token-demo content (e.g. `max-w-sm`/384px square, `--radius-card` corners, centered or left-anchored in the first fold), positioned above or beside the type/color specimen blocks so the eye lands there first, then reads down into the wordmark, headline demo, and swatches as supporting proof of the system. The wordmark in the header remains a secondary, expected anchor (per standard nav conventions) but is not the page's primary focal point.

### Container

- Max-width: **1280px** (`max-w-7xl`), `mx-auto`
- Horizontal gutter: `px-4` (16px) mobile → `md:px-6` (24px) tablet → `xl:px-8` (32px) desktop
- Full-bleed exception: hero background art (Phase 3) may extend edge-to-edge outside this container; header/footer bars are full-width `--color-surface` bands with the container nested inside for content alignment

### Header contract

- Full-width `--color-surface` band, sticky to top (`sticky top-0 z-50`), height ~64px mobile / ~72px desktop, subtle bottom hairline (`border-b border-white/5`) — not a hard color-block edge
- Layout: flex row, `justify-between items-center`, container-constrained
  - **Left:** DARLNG wordmark (see Wordmark treatment above), links to `/`
  - **Right:** social follow icon row — Spotify, Instagram, Facebook, YouTube, TikTok (order matches CONTENT.md listing) — each a 44×44px tap target, `gap-2` (8px) between icons on mobile, `gap-4` (16px) on desktop
- **375px behavior:** wordmark + 5 icons at 44px targets with 8px gaps is tight but fits (~120px wordmark + 220px icons + 32px gaps ≈ 372px against 343px available content width after gutters is snug — verify in browser at build time). If it does not fit cleanly, the fallback is: icons wrap to a second row below the wordmark (still `flex justify-center`, same gap/size rules) — **never** hide or drop an icon on mobile.
- No hamburger/nav-links menu this phase — there are no other pages/sections to link to yet (Phase 3 may add in-page anchor nav; that's a future contract addition, not a gap in this one)

### Footer contract

- Full-width `--color-surface` band, `py-12` mobile / `py-16` desktop
- Mobile (`<768px`): single column, `flex-col items-center gap-6 text-center`
  1. Wordmark (small, `text-lg`, non-linked or links to `/`)
  2. Genre line: **"Afro / RnB / Pop"** — `text-sm`, `--color-text-muted`, `tracking-wide`, uppercase optional (lowercase reads slightly more confident/less shouty — use as-written, sentence case, no uppercase transform)
  3. Social icon row (same 5 icons/order as header, 44×44px targets, `gap-4`)
  4. Copyright line: `text-sm`, `--color-text-muted` — "© 2026 DARLNG. All rights reserved."
- Desktop (`md:` and up): 3-column grid (`md:grid md:grid-cols-3 md:items-center md:text-left`)
  - Col 1: wordmark + genre line stacked
  - Col 2: social icon row, centered
  - Col 3: copyright, right-aligned
- Genre line and copyright are `static-content` — fixed, short, authored strings; no truncation/overflow risk at any tested viewport

### Icon implementation (zero-JS, brand + generic glyphs)

Lucide (`lucide-astro`) does **not** ship brand marks (no Spotify, Instagram, Facebook, YouTube, or TikTok glyphs — Lucide is a generic/UI icon set only). For the five social platforms:

- Install `simple-icons@^16.28.0` (data package — exports icon path objects, not components: `siSpotify`, `siInstagram`, `siFacebook`, `siYoutube`, `siTiktok`, each with a `.path` SVG path string)
- Author one small `BrandIcon.astro` component that takes an icon-path-object prop and renders `<svg viewBox="0 0 24 24" fill="currentColor"><path d={icon.path} /></svg>` — `currentColor` inherits `--color-text-muted` by default and `--color-accent` on hover/focus via a Tailwind `group`/`[&:hover]` pattern, so no per-icon brand-color hardcoding is needed (keeps everything on-token, dark-theme-consistent, and matches the single-accent-color mandate rather than 5 different brand hex colors clashing with the jewel accent)
- This is pure inline SVG — zero JS, fully tree-shakable (only the 5 imported icons ship, not the full `simple-icons` set)
- Generic UI glyphs (external-link indicator, play icon, chevrons — as needed in later phases) continue to use `lucide-astro` per project CLAUDE.md convention

### Interaction states (system-wide, applies to every link/button/icon this phase and beyond)

- **Hover** (pointer devices): color transition to `--color-accent`, 150ms ease; icon links additionally get a soft glow — `box-shadow: 0 0 12px color-mix(in oklch, var(--color-accent) 40%, transparent)`
- **Focus-visible** (keyboard): `outline: 2px solid var(--color-accent); outline-offset: 2px` on every interactive element — never removed without this replacement. Border-radius of the outline matches the element (`rounded-full` icons get a round outline via the browser's default outline-follows-radius behavior in modern browsers, or an explicit `outline-offset` adjustment if needed)
- **Active/pressed**: slight scale-down (`active:scale-95`) on buttons/icon links, 100ms — reinforces tactility without needing JS

### Button contract (architecture for Phase 3's CTAs — not built this phase, tokens ready)

| Variant | Background | Text | Border | Radius | Padding |
|---------|-----------|------|--------|--------|---------|
| Primary | `--color-accent` | `--color-bg` (dark text on accent fill, 11.22:1) | none | `--radius-pill` (full) | `py-3 px-6` (12px/24px) |
| Secondary/ghost | transparent | `--color-accent` | `1.5px solid --color-accent` | `--radius-pill` (full) | `py-3 px-6` |
| Secondary hover | `--color-accent` at 10% opacity fill | `--color-accent` | unchanged | unchanged | unchanged |

Pill-shaped (`rounded-full`), not the safer `rounded-md` — a deliberate "pop"/contemporary-music-brand choice, distinct from typical corporate rounded-corner buttons.
